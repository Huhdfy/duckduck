# MicroDuck 实验记录规范 v1.1

本规范定义新实验的记录、汇总、绘图和展示板读取方式，适用于 MicroDuck 平地速度跟踪任务。
由 AI 负责按本规范整理实验记录、核算指标、制作表格和图像、撰写结论，并保留原始数据与冻结配置。
不要求开发一套自动生成研究结论的脚本；AI 可以按任务需要使用计算/绘图工具，但须核对结果。

**使用方式：**实验或结果复核完成后，让 AI 阅读本规范并整理记录。AI 最后在
`logs/experiments/<study_id>/experiment.json` 发布清单；用户打开展示板点击 **刷新记录** 即可载入。
读取服务只做扫描、格式/引用校验和展示数据打包，不训练、不仿真、不重新统计、不生成图或研究结论。
浏览器刷新页面也会检查是否有新清单；仅更新 Markdown 而不写入口清单的新目录不会自动收录。
已有历史记录继续保留，AI 不得为了收录而重跑实验或覆盖原始报告。

## 1. 基本约定

- 人读的名称、表头、图例用中文；程序字段与实体 ID 用稳定英文标识，不随显示名称更改。
- 一次研究可以包含多组变体、多次训练和多次评估；不把“模型”“训练运行”“评估运行”当作同一个实体。
- 主要结论依据统一物理指标，同时报告稳定性、失败情况与有效样本数。
- 训练回报仅解释同一奖励定义下的学习过程；奖励定义不同的模型不按训练总回报排名。
- 每项指标规定单位、坐标系、采样时刻、时间窗口、公式和统计粒度；定义变化需要新版本。
- 缺失为 `null` 并带原因，不填成零；失败、中断和不支持的历史数据也保留目录记录。
- 不修改第三方库，不改变训练算法以满足记录要求。采集器、导出器与展示板读取器分别维护。

## 2. 实体与易读名称

### 2.1 身份关系

| 实体 | 标识示例 | 含义与唯一性 |
|---|---|---|
| 研究 | `md-20261029-reward-shape-01` | 一个问题、一套冻结的实验设计；目录 ID 创建后不改 |
| 变体 | `baseline`、`v-std-015`、`w-std-035`、`w-rational-035` | 研究内的配置方案；保存相对匹配参照的精确修改 |
| 训练运行 | `w-rational-035-s123-r01` | 一次实际训练尝试；重新运行使用新的 r 编号，不能覆盖 |
| 模型 | `sha256:<完整检查点哈希>` | 按检查点内容去重；同一模型可被多项研究引用 |
| 评估运行 | `w-rational-035-s123-e42-r01` | 一个模型、一个冻结评估协议和一次评估尝试 |
| 试验 | `<evaluation_id>/<case_id>/t00` | 某档指令下的一次固定时长轨迹 |
| 分析版本 | `a001` | 一次指标计算和图表生成；修正算法时生成 a002，保留 a001 |

显示名称示例：

| 短名称 | 默认补充信息 | 禁止含糊的写法 |
|---|---|---|
| 原始基线 | 检查点 6000；新增更新 0 | 把它和续训基线都叫 Baseline |
| 续训基线 | 6000 → 9999；新增 4000；种子 123 | 仅写“10000 轮”并丢掉原生编号 |
| 线速度 std 收紧 | σv=0.15；σω=√0.5 | 小 std，而不说明哪一个 std |
| 角速度 std 收紧 | σv=√0.1；σω=0.35 | 角速度优化组，而未定义修改 |
| 双 std 收紧 | σv=0.15；σω=0.35 | 与单项 std 修改混用同一个名字 |
| 角速度有理函数 | σω=0.35；参照为“角速度 std 收紧” | 默认把 Baseline 当作唯一匹配参照 |

图例默认使用短名称。跨种子时追加“· s123”；跨研究时追加研究简称。
检查点编号、实际新增 PPO 更新数、累计训练更新数必须分别记录；不能从文件编号推算新增更新数。
同一原始检查点之后的三个续训种子，称为“续训种子验证”，不称为“从零训练的三个独立种子”。

### 2.2 实验开始前人工填写的最小信息

研究名称、问题/假设、变体及唯一修改、每个变体的匹配参照、主要指标、保护指标和判定门槛。
其他信息由 AI 从解析后配置、训练入口、日志和真实结果中整理；入口已有记录时直接复用，不要求用户手工填表。
门槛、样本量、分组阈值及候选选择顺序在运行前冻结，不在看到结果后追改。

## 3. 冻结训练与评估条件

### 3.1 训练运行必须保存

任务 ID、物理后端及求解器、环境数量、种子、设备与软件版本、控制周期/物理步长/decimation、
每轮采样步数、算法完整配置、观测与动作定义、归一化方式、执行器延迟、随机化、
指令采样分布、全部奖励及课程定义、启动参数、开始/结束时间和耗时。

MicroDuck 当前研究的默认训练条件为 **4096 环境、Newton MJWarp、每轮 24 个控制步**；
续训研究默认从指定 6000 检查点新增 4000 次更新，但这些属于研究配置，不硬编码进通用读取器。

续训另外保存：

- 起点与终点检查点路径、SHA256、原生 iteration、新增更新数和观测到的恢复状态。
- actor、critic、归一化、优化器及优化器状态是否实际恢复；预期与实际学习率。
- 课程步数、恢复时机及首次重置后的有效奖励权重/指令范围。
- 仿真与随机流是重新初始化还是完整恢复；当前研究采用前者。
- Git commit、分支、dirty 标记、相关源文件哈希、未提交补丁及影响运行的未跟踪源文件快照。

Baseline 的 σv 保存为解析数值 `sqrt(0.1)`，σω 保存为 `sqrt(0.5)`，同时可保留原始表达式。
禁止用显示时四舍五入的 0.316/0.707 反写配置。

### 3.2 默认评估协议

| 项目 | 默认值 |
|---|---|
| 任务与后端 | 原 MicroDuck 平地任务，Newton MJWarp；版本和求解器参数冻结 |
| 策略 | 确定性推理；不更新参数；保存观测归一化状态和配置 |
| 评估种子 | 42；与训练种子分开记录 |
| 每档试验 | 16 条；并发环境数单独保存，不把它当作训练环境数 |
| 每条试验 | 20 s；前 3 s 预热 |
| 指令 | 站立；前进 0.1/0.2/0.3/0.4 m/s；原地转向 −0.5/+0.5 rad/s |
| 其他指令 | 横向速度为零；身体/头部指令固定；实际值写入协议 |
| 初始化 | x/y/yaw 等重置条件固定；实际初始状态、随机化结果与配对标识保留 |
| 课程 | 成熟课程；记录有效配置和步数 |
| 扰动 | 默认无推力；其他噪声和随机化必须明确列出，不能只写“默认” |
| 速度坐标系 | `root_link` 的机体系，与现有统一评估一致 |
| 采集时刻 | 物理推进、奖励计算之后；环境重置、指令重采样之前 |

`protocol.json` 保存以上所有条件和解析后的评估配置哈希；`protocol_id` 用于显示，
`protocol_sha256` 对规范化 JSON 内容计算，作为一致性核对依据。
协议中排除模型路径等与评估条件无关的字段；模型、硬件及代码信息由评估记录另行关联。
物理/观测/执行器/初始化设置、指标定义版本改变时，不能仅沿用旧协议名称宣称可比。
模型训练时的奖励定义可不同；物理评估保持一致，训练口径评分单独保存。

固定时长累计回报包含预热；物理表现默认只用预热后、首次终止前的有效样本。
终止步保留，重置轨迹不纳入。失败后不另接一条轨迹补足 20 s。

## 4. 默认记录的指标

记一条试验预热后有效样本集合为 S，机体系实际速度为 v，指令为 vcmd、ωcmd。
以下时间均值只在 S 内计算；无有效样本则为 null。

### 4.1 物理表现：每次评估必需

| 中文名称 | 稳定字段 | 单位 | 单条试验定义 |
|---|---|---|---|
| 实际前进速度 | `vx_mean_mps` | m/s | mean(vx) |
| 实际横向速度 | `vy_mean_mps` | m/s | mean(vy) |
| 实际偏航角速度 | `yaw_rate_mean_radps` | rad/s | mean(ωz) |
| 平面跟踪误差 | `planar_error_mean_mps` | m/s | mean(sqrt((vx−vcmd_x)²+(vy−vcmd_y)²)) |
| 偏航误差偏置 | `yaw_error_mean_radps` | rad/s | mean(ωz−ωcmd)；带符号 |
| 偏航误差 RMS | `yaw_error_rms_radps` | rad/s | sqrt(mean((ωz−ωcmd)²)) |
| 横滚角速度 RMS | `roll_rate_rms_radps` | rad/s | sqrt(mean(ωx²)) |
| 俯仰角速度 RMS | `pitch_rate_rms_radps` | rad/s | sqrt(mean(ωy²)) |
| 横滚俯仰角速度 RMS | `roll_pitch_rate_rms_radps` | rad/s | sqrt(mean(ωx²+ωy²)) |
| 综合角速度误差 RMS | `angular_error_rms_radps` | rad/s | sqrt(mean((ωz−ωcmd)²+ωx²+ωy²)) |
| 前进运动比例 | `motion_ratio` | 1 | mean(vx)/vcmd_x，仅 vcmd_x>0 时定义 |
| 稳定段有效时长 | `stable_duration_s` | s | 有效稳定样本覆盖的控制周期总时长 |

“平面误差”默认是上表的平均范数，**不是** RMS，也不是平均速度与指令的差。
综合角速度误差也不能用已汇总的各模型均值再开方重建。
身体角度、足部步态等可作为扩展项；不要把角速度 RMS 标成横滚/俯仰“角度”。

### 4.2 稳定性与样本质量：每次评估必需

每条试验保存：`completed`、`fell`、`termination_reason`、全部触发的终止项、
终止步/存活时长、有效状态步数、非有限状态/奖励数量和预热后样本数。
若多个原因同时出现，全部保留，再按冻结规则确定主原因。

- 完成率：到达预定评估终点且无提前终止的试验数 / 请求试验数。
- 摔倒率：发生摔倒的试验数 / 请求试验数。
- 异常率：提前发生数值或非预期终止的试验数 / 请求试验数。
- 预定 20 s 结束属于完成；20 s 前的 TimeLimit 等终止要按实际原因分类。
- 另报 `n_requested`、`n_recorded`、`n_completed`、`n_valid_complete`、`n_valid_partial`。
  无任何有效稳定样本的试验不进入物理均值，但仍计入请求数和失败率。
- 丢失的试验不能默认为成功、摔倒或零奖励；标为缺失，并阻止“完整结果”验收。

默认物理均值包含失败试验中可用的终止前稳定样本，标注为 `all_valid_preterminal`。
同时保存 `completed_only` 的敏感性汇总；不能悄悄只留下成功轨迹。
部分轨迹指标和完成率必须一同查看，短时存活不能被解释为总体稳定性更好。

### 4.3 奖励：每次评估必需

每个实际启用的奖励项均记录，不只记录线速度与角速度两项：

- 内部 term_id、中文名称、函数/shape、有效权重、std/其他参数、课程状态和单位。
- 每控制步原始项值（可直接获得时）、加权未乘 dt 的贡献、乘 dt 后的步贡献。
- 训练口径与成熟 Baseline 参照口径；各项固定窗口累计贡献和总回报。
- 原始环境奖励及逐项求和误差，注明环境奖励采用哪套口径。

定义：`contribution = weight × raw_value`；`reward_step = contribution × control_dt_s`；
`return = sum(reward_step)`。对每条存活轨迹分别核对求和，再按试验等权汇总。
累计窗口从 0 s 开始，包括预热；提前终止后的部分不填补、不按存活时间放大。
若有裁剪、归一化、终止附加奖励等，另外保存相应变换及前后总量，不能套用不成立的求和式。

参照奖励中的空中时间、摆动峰值等有状态项必须通过同步的奖励状态/管理器获得；
不能声称只凭单帧速度即可离线重建全部参照奖励。无法得到时标记缺失，暂停对应 H2 比较。
当前工具使用 Baseline 评估环境采集参照奖励，再对已知无状态修改项重算训练口径；
记录中须声明此来源，并分别核对参照总量和重算总量，不能把重算值冒充训练环境原始返回值。

### 4.4 动作执行：默认诊断项

保存 14 个动作关节的名称与顺序、原始策略动作、processed_actions、编码器偏差、
物理目标角 `q_target=processed_actions−encoder_bias`、推进后的真实关节角、
动作变化幅度、逐关节误差及 RMS/超容差比例，区分腿部与头部。

目标与实测按当前控制步对齐，不做延迟平移；保留执行器延迟说明。
超容差比例必须关联冻结的逐关节容差文件和哈希；无容差时记 null，不临时猜阈值。
若任一项不可采集，必须显式说明，不改变现有动作链路来伪造“实际输出动作”。

### 4.5 训练曲线：每次实际训练必需

每次 PPO 更新记录：新增更新编号、原生 iteration、累计环境控制步数、采样 transition 数、
墙钟时间、平均训练回报、回合长度、逐项奖励、Actor/Critic loss、熵、实际学习率、
KL（框架可提供时）、吞吐量、课程值和失败统计。原生 TensorBoard 与中文显示映射同时保留。

横轴默认是“新增 PPO 更新”，前 500 次更新提供局部图；性能耗时另用墙钟时间。
4096 环境、24 步 rollout 时，区分“每环境控制步数”和“总 transition 数”，不能混成同一个步数。
未训练的复用模型指向原训练运行，不补造一份训练曲线。

## 5. 统计与比较规则

1. 先在每条试验内计算均值、RMS、累计回报，再在同一模型/档位/统计口径内等权平均。
   不把存活更久的试验赋予更高权重，也不先混合全部步再计算模型级 RMS。
2. 每个汇总值保存 mean、std、95% bootstrap 区间、请求数、有效试验数和完成数。
   Bootstrap 默认 10000 次、随机种子 42；算法、版本和样本量写入分析元数据。
   n<2 时不提供区间；不把零宽区间或 16 次全成功解释为风险为零。
3. 完成率/摔倒率/异常率使用全体已核对的请求试验为分母；同时保存 Wilson 95% 区间。
   试验缺失时不给完整完成率结论，明确显示“数据不完整”。
4. 相对差异的参照是显式 `control_variant_id`。更小为好的指标改善率为
   `(control−candidate)/control`；参照接近零时记 null 并报告绝对差。
   近零阈值按指标单位在指标字典中定义；比例变化与百分点变化分别命名。
5. 只有初始条件、扰动序列及 trial pairing_id 被核对一致才使用配对差值 bootstrap。
   相同评估种子本身不是配对证据。否则使用明确标注的非配对重采样。
6. 多档综合指标先按试验、再按档位等权；必须列出纳入档位，不能通过样本数不均隐式加权。
7. 每个续训种子分别报告候选与匹配参照的差值。多种子置信区间以训练种子为外层单位；
   种子少时优先逐个展示，不把同模型的 16 次评估当成 16 次独立训练。
8. 完成试验的分组、低速运动程度分类与异常剔除规则在分析前冻结，并保存原始分类结果。
   H2 默认低运动为 0≤mean(vx)/vcmd_x<0.2，较好跟踪为 0.8–1.2；倒退单列。
   站立和原地转向不使用这一比值。没有同模型同指令的可比样本则报告证据不足。

## 6. 默认展示的表格

AI 根据同一版本的结构化数据制作数值表，并核对其与报告和图一致。显示通常保留三位小数；底层保留完整精度。
“—”代表缺失/不适用，不代表零。点击数值可查看 n、区间、源评估与指标定义。

| 表格 | 行粒度 | 必须列 | 默认位置 |
|---|---|---|---|
| 模型与训练信息 | 每个模型/训练运行 | 易读名称、唯一修改、匹配参照、训练种子、起点/终点、新增更新、配置/模型哈希 | 实验详情 |
| 速度表现总览 | 每个模型与种子 | vx@0.1/0.2/0.3/0.4，ω@−0.5/+0.5，完成数/请求数 | 首页/报告首表 |
| 逐档质量与稳定性 | 模型×种子×指令档位 | 指令、实际 vx/ω、平面误差、偏航/综合角速度 RMS、横滚俯仰 RMS、完成/摔倒/异常率、有效 n | 对比页 |
| 相对匹配参照变化 | 候选×种子×档位×指标 | 参照名、候选/参照值、绝对差、改善率、差值区间、门槛是否通过 | 对比页 |
| 奖励分解 | 模型×种子×档位×评分口径×奖励项 | 权重/参数、平均步贡献、固定窗口累计贡献、总回报、有效样本数 | 奖励分析 |
| 数据核验 | 评估/分析版本×检查项 | 请求/收到试验、缺失/非有限数、哈希、奖励求和误差、独立重算误差、通过/失败/不适用 | 详情底部 |
| 多种子对照（条件） | 候选×匹配参照×训练种子 | 主指标差值、各保护指标、整体门槛、种子来源 | 存在多个训练种子时 |

沿用现有复核报告的首页结构，例如以下**已有结果**（续训种子 123；不是新增评估）：

## 7. 默认绘制的图与选数规则

### 7.1 每次评估的核心图

| 图 | 横轴 / 分组 | 纵轴 | 数据来源与选数 |
|---|---|---|---|
| 前进指令响应 | 四个目标 vx，真实数值间距 | 实际 vx，均值与 95% 区间；带 y=x 参考线 | 同协议、同种子、各档逐试验均值；默认最多 5 个模型，更多时筛选/分面 |
| 前进跟踪误差 | 四个目标 vx | 平面误差均值与区间，越低越好 | 与响应图同一批试验，含有效失败片段并同时给完成率 |
| 直行偏航与姿态 | 站立与四档前进分面 | 偏航 RMS、横滚俯仰 RMS 分图，rad/s | 逐试验 RMS，不以正负偏差相互抵消 |
| 原地转向 | −0.5、+0.5 两档分别显示 | 实际 ωz 与指令参考；纯偏航 RMS、综合角误差 RMS 分图 | 两方向分别报告，不先平均正负实际角速度 |
| 完成与失败 | 各指令档位 | 完成率、摔倒率、异常率及请求数 | 全部请求试验与终止分类；不把可能重叠的失败原因强制堆叠成 100% |
| 代表性时间序列 | 控制时间 t，标出 3 s 预热 | vx 与指令、ωz 与指令、横滚/俯仰角速度 | 固定 t00；另外显示首个失败试验（若有），不能挑最好看的一条 |
| 训练过程（有训练时） | 新增 PPO 更新；前 500 更新另给放大图 | 同定义训练回报、逐项奖励、Critic loss、学习率分图 | 每次更新的原始聚合；多种子分线，不做逐步样本伪置信带 |

### 7.2 奖励机制研究增加的图

| 图 | 所用数据 | 必须说明 |
|---|---|---|
| 奖励–误差曲线 | 从冻结公式、权重、std 计算的规则网格 | 标记 `analytic`，不是采样轨迹；横轴是 err 还是 E；是否乘 dt；有理核相对哪个 std |
| 角误差/归一化误差分布 | 逐步 Eω 与 x=Eω/σω²，按指令档位分开 | 优先逐试验 ECDF 后等权平均；不能用所有幸存步混池代表平均试验 |
| 奖励响应分布 | 训练口径 r/w 与参照口径 r/w 分开 | 每个模型使用自身核函数；x≥3 叫高误差区，有理核不能称其为低于 5% 奖励区 |
| 高误差比例与误差降低收益 | 每试验 x≥3 比例；误差平方和降低 10% 的 Δr/w | 指数核为 exp(−0.9x)−exp(−x)；有理核为 1/(1+0.9x)−1/(1+x)；不称为 PPO 梯度 |
| 低速奖励竞争 | 同模型同指令的低运动/较好跟踪完整试验 | 统一参照评分、每项累计贡献的组间差值；缺少可比样本显示不足，不画虚构对照 |
| 关节执行误差 | 各关节逐试验 RMS、超容差比例 | 腿/头分组、关节顺序、冻结容差与目标时序 |
| 多种子效果图 | 每个训练种子的候选−匹配参照差值 | 每种子单独一个点；注明共享同一续训起点，不只画一个跨种子均值 |

同一研究中颜色固定对应同一变体；种子用线型/分面区分，不每张图重新分配颜色。
所有图包含指标单位、统计口径、分析版本、样本数/缺失提示；原始均值和区间可导出。
绘图区保留未平滑数据；若显示平滑训练线，必须注明窗口并能查看原始线。
直方图使用冻结的共同 bins 和归一化规则；ECDF 和连续数值曲线保留真实数值横轴。

每幅图另存同名 `.plot.json`，记录 `figure_id`、`kind`（empirical/analytic）、数据文件、
过滤条件、字段、聚合顺序、区间算法、坐标范围、图例/颜色和公式参数。
需要降采样的时间序列保留终止事件和极值，记录方法；统计指标仍使用全量数据。
没有可靠数据的图给出缺失原因，不创建空白“成功图”。

examples/demos/microduck_experiment_records.md    # 本规范，随代码管理
logs/
  experiments/
    <study_id>/
      experiment.json                           # 研究清单、变体、主要指标、结果索引

      variants.json                             # 每组配置差异与匹配参照

      configs/                                  # 研究公共训练配置、参照奖励配置
      runs/
        <run_id>/
          run.json                              # 训练状态、种子、恢复记录、命令、模型引用
          resolved_config.json                  # 本次解析后完整配置
          training_metrics.jsonl                # 一行一次 PPO 更新
          console.log
          tensorboard/                          # 或已存在目录的受校验引用
          checkpoints.json                      # 原路径+哈希+iteration，默认不复制大模型
      evaluations/
        <evaluation_id>/
          evaluation.json                       # 模型引用、状态、协议/配置/源码哈希
          protocol.json
          trace_metadata.json                   # 数组、列、单位、坐标系、dt、采样阶段
          trials.jsonl                          # 一行一条试验的身份、终止和物理指标
          reward_terms.jsonl                    # 试验×评分口径×奖励项的累计与步均值
          initial_conditions.npz                # 初始状态、随机化结果与配对条件
          traces/<case_id>.npz                   # 全量控制步状态、动作、奖励、有效掩码
      analyses/
        a001/
          analysis.json                         # 输入清单及哈希、指标字典版本、生成方法
          summary.json                          # 面板读取的长表、区间和样本数

机器权威数据使用 JSON/JSONL；NPZ 保存数组，禁止依赖 pickle/object 数组。
CSV 用 UTF-8 BOM 便于表格软件打开；AI 制作 Markdown、图和 CSV 时均引用同一分析版本。
逐步时序保存 float32 或更高精度，时间/身份/掩码有独立字段；计算汇总使用 float64。
允许保留现有 NPZ 的 `(step, trial, column)` 结构，但 metadata 必须逐列给出类型、单位和意义。

### 8.1 最小逐步字段

`trial_id`、`control_step`、`time_s`、`alive_before_step`、`terminal_this_step`、
`state_finite`、`reward_finite`、指令 xyz/yaw、实际机体系线/角速度、物理关节目标与实际角、
逐项训练/参照奖励贡献、环境总奖励、终止原因引用。

metadata 另外记录采样前后时序、关节顺序、root/body 定义、四元数顺序、
物理/控制 dt、预热切片规则、padding 与无效字段的 NaN 语义。
时间戳为该步物理推进结束时刻，例如 `t=(step+1)*control_dt_s`，不把重置状态写成终止状态。
状态非有限值和稀疏事件“尚未发生”的 NaN 分别统计；JSON 输出禁止 NaN/Infinity。

### 8.2 保留与引用

默认保留所有评估轨迹、逐试验结果、完整训练曲线、配置/源码快照、正式起点与终点模型引用。
不默认保存 4096 个训练环境的每步全状态；只在诊断时按事先选定环境/时间窗口记录。
视频不是指标的替代品，默认可选；保存时关联模型、档位与 trial_id。

新记录的文件引用写为 `{root: "study"|"repository", path: "...", sha256: "..."}`。
路径相对指定根目录、禁止 `..` 越界；检查点位于现有 `logs/rsl_rl/` 时使用 repository 根，
不为了归档重复复制大文件。导出可移植归档时检查依赖是否齐全，不把本机绝对路径当网页链接。
历史目录原地保留，通过适配器读取；修正结果新增分析版本并标记取代关系，不改写旧结论。

## 9. 程序读取的数据约定

以下 JSON 是**结构示例，不是新增实验记录**。下文第 9.4 节是当前读取服务支持的最小接入格式；完整分析档案由 AI 按本规范整理。
所有记录必须带 `schema_version`；所有时间采用含时区的 ISO 8601；哈希保存完整 SHA256。

### 9.1 研究入口 experiment.json

`runs`/`evaluations` 中每项为记录文件引用；`latest_analysis` 指向通过结构校验的 analysis.json。

### 9.2 summary.json 的长表行

`summary.json` 是对象，包含 schema_version、study_id、analysis_id、输入哈希和 `rows`。
每行粒度为“评估运行×档位×指标×样本口径×评分口径”。实体信息通过 ID 关联，不从中文名称解析。

{

  "train_seed": 123,

  "metric_id": "vx_mean_mps",
  "unit": "m/s",
  "sample_scope": "all_valid_preterminal",
  "score_scope": "physical",
  "window": "post_warmup",
  "mean": null,

  "ci95_high": null,

`score_scope` 取 physical/training/reference；奖励指标必须另外带 `reward_term_id`。

### 9.3 指标字典与表格配置

每项指标的注册信息包含：`metric_id`、中文 label、unit、方向（lower/higher/target/neutral）、
formula、required_columns、frame、window、sample_scope、aggregation、near_zero_threshold、
版本和可适用的 case 类型。
表格/图的字段选择使用 metric_id，不依赖 Python 列顺序或中文翻译。
新增指标可以增加可选字段；公式、单位或默认统计口径改变时升级定义版本。
不支持的主版本显示“版本不支持”，不能靠字段猜测继续排名。

### 9.4 当前展示板的最小接入格式（AI 负责填写）

只展示报告时，AI 在研究目录保存以下清单即可。此例为待开始的结构示例，不是实测结果：

```json
{
  "schema_version": "microduck.experiment/1.0",
  "study_id": "md-20261029-example-01",
  "display_name": "角速度奖励形状对照",
  "created_at": "2026-10-29T12:00:00+08:00",
  "status": "planned",
  "type": "奖励机制",
  "question": "角速度奖励形状是否影响转向？",
  "summary": "计划已冻结，尚未采样。",
  "quality_status": "pending",
  "review_status": "unreviewed",
  "training_runs": 0,
  "reports": [{"root": "study", "path": "report.md", "role": "实验报告"}]
}
```

status 只能取 planned/running/completed/failed/interrupted；未完成或质量未 passed 的记录
仍显示报告和状态，不进入完整模型对比。相对路径默认以研究目录为根，也可显式指定 repository。
报告引用的 PNG/JPEG 图片随记录载入；清单里的字段不是让用户手填，而是 AI 的交付要求。

要展示模型曲线，在清单中增加 `"board_data": {"root": "study", "path": "board_data.json"}`，
并声明真实的 quality_status；不允许为了让曲线出现而假称 passed。
board_data.json 格式如下（字段类型示例，实际值由 AI 从真实数据填写）：

- schema_version：`microduck.board/1.0`。
- protocol：id、sha256、metric_version、eval_seed、trials_per_case、duration_s、warmup_s。
- protocol_file：冻结协议文件引用；sha256 必须与文件实际内容匹配。
  协议文件含上述字段（不含 sha256 本身）及后端、坐标系、初始化、随机化等完整条件。
- models：列表。每项为 key、name、variant、seed、checkpoint 文件引用（含完整 sha256）、
  start（允许 null）、end、updates、trainEnvs；key 和 variant 使用英文数字/连字符/下划线。
- metrics：列表，每项粒度是“模型×档位”，不是逐步样本。字段映射见下表。

| 展示字段 | 规范指标或含义 |
|---|---|
| model_key | models 中的 key；一个模型不能重复同一 case |
| case | standing / forward_0.1 / forward_0.2 / forward_0.3 / forward_0.4 / turn_negative / turn_positive |
| targetVx、targetYaw | 实际评估指令，单位 m/s、rad/s |
| vx、yaw | vx_mean_mps、yaw_rate_mean_radps 的逐试验等权汇总 |
| planarError | planar_error_mean_mps |
| yawRms | yaw_error_rms_radps |
| angularRms | angular_error_rms_radps |
| jointRms | 关节跟踪误差 RMS；未采集为 null |
| completion | 完成率，0–1 |
| trials、validTrials | 每档请求试验数、该物理均值的有效试验数 |

这些字段只作为当前展示板的适配视图；完整指标、区间和失败分类仍保存在标准分析档案与报告中。
AI 不必改写展示板源码，也不必编写新的导出脚本。读取器只做字段映射，不从表格截图提取数值、
不将 Markdown 表格猜成指标、不替 AI 进行逐试验统计。

复用原始模型时引用实际训练种子，不写成当前研究的新训练。
不同协议 SHA256 或指标版本的模型分组显示；历史快照尚未补齐协议指纹时与新协议记录分开，
不得为了跨组比较而伪造相同协议。

## 10. 完成、核验与展示板收录

### 10.1 三种状态分别维护

- 运行状态：planned → running → completed / failed / interrupted；completed 表示运行结束，
  不代表模型通过性能门槛。续跑或重试另建 attempt，保留原失败记录。
- 数据质量：pending / passed / failed / incomplete；由 validation.json 的实际检查决定。
- 复核状态：unreviewed / automatic_verified / reviewed；仅有 review.md 文件不代表已核验。
  复核记录保存依据、时间、作者/工具与核验项，不将 AI 撰写自动等同独立审查。

### 10.2 发布流程

```text
结束采集 → AI 核算逐试验指标 → AI 整理汇总、图与结论 → AI 核验数据
        → 写 analysis.json/validation.json → 原子更新 experiment.json 的版本引用
        → 用户点击刷新记录 → 读取服务校验并载入 → 按协议和指标版本分组比较
```

- 先在新 analysis 目录生成完整结果，最后通过同目录临时文件+rename 更新入口清单。
- 完整比较至少检查：实体 ID 唯一/引用可解析、配置与声明修改一致、模型/输入哈希匹配、
  每档预期试验数量、时间索引/终止掩码、单位/坐标系、奖励求和、独立指标重算和文件引用。
- 默认奖励求和容限 `atol=2e-6, rtol=2e-5`；独立重算物理指标默认 `atol=2e-6, rtol=2e-5`。
  保存精度、检查数、最大误差和失败项；不同精度需运行前声明容限，不事后放宽来通过。
- QC 检查数据真实性和完整性。机器人摔倒或指标变差属于实验结果，不应因此标为数据损坏。
- 失败/中断/不完整记录也入总览；不完整记录默认不进入完整对照排名，可单独查看已采集部分。
- 通过数据校验但未复核的结果允许展示，显著标识“未复核”；复核通过后仍保留原自动报告。

### 10.3 展示板读取规则

1. 扫描 `logs/experiments/*/experiment.json`，读取 schema、身份、状态、版本引用和摘要。
   不靠目录编号、模型显示名、报告文本或文件是否存在猜测实验状态。
2. 幂等索引键为 study_id / analysis_id / evaluation_id；按模型哈希去重模型，不合并不同评估。
3. 首页只加载清单和 summary；用户打开详情/曲线时再加载报告、plot 配置和所需轨迹。
   避免每次刷新读取全部 NPZ 或重复计算大检查点哈希；校验结果需绑定文件内容指纹。
4. 仅协议、指标定义和统计口径匹配时提供直接比较；允许奖励定义不同的物理对照，
   奖励面板则明确分开训练/参照口径。其他差异列出并默认分组展示。
5. 展示当前分析版本与复核状态；保留历史版本切换，重评估不覆盖上一条 evaluation。
6. 索引失败隔离到单条记录并显示原因，不能静默丢弃记录或中断全部历史浏览。
7. 页面显示“数据截至何时”和最近索引时间。训练中快照标 partial，不能看起来已完成。
8. 删除索引缓存可从清单重建；展示板绝不修改模型、原始轨迹或已冻结分析数据。

## 11. 报告的固定结构

1. 问题与唯一修改；匹配参照、主要指标与保护指标。
2. 模型身份和控制条件；起点、终点、新增更新、种子、实际恢复状态。
3. 速度表现总览；逐档质量/稳定性与样本量。
4. 相对参照变化；多种子结果与门槛。
5. 奖励分解及适用的机制图；区分公式性质与观察到的行为。
6. 结论：观察事实、支持/反驳的假设、替代解释、证据不足之处。
7. 数据核验、缺失、失败记录和原始数据入口。

不要求每次都有正结果；“未改善”“保护指标恶化”“证据不足”“分支未启动”都是有效结果。

## 12. AI 执行清单与当前边界

每次完成 MicroDuck 实验/评估/复核，AI 应依次：

1. 阅读本规范，定位真实输入、日志、配置和检查点，确认实验名称与匹配参照。
2. 使用已有原始数据计算本次适用指标；需要新采样时区分评估与训练，不擅自补跑训练。
3. 整理默认表格与适用图像，保存图的数据范围、公式、单位和选数方法。
4. 写报告，区分观察事实、假设支持程度、限制与替代解释，保留失败和缺失。
5. 若要进入模型对比页，按第 9.4 节整理 board_data.json，并核对数值、协议和模型哈希。
6. 在临时文件中写实验清单，最后 rename 为 experiment.json；图片/报告先写完，清单最后发布。
7. 告知用户记录目录和展示板入口，用户点击“刷新记录”即可看到新记录；无需再次让 AI 更新页面代码。

当前读取服务已支持：扫描清单、读取报告与本地图片、读取已汇总指标、动态实验/模型选择、
按协议分组、错误隔离、重新读取后的页面更新。它不负责生成科学内容，也不替代 AI 的数据核验。
旧版数据保留为已核对的历史快照；只有新清单声明的记录会增量收录。

当前未实现：全量 JSON Schema 工具链、逐步数据浏览器、分析版本切换控件、后台定时扫描。
这些不是“AI 写记录 + 用户点击刷新”的前置条件。完整默认图表可以在 AI 报告中查看，
不要求把每种研究图都改造成独立展示板组件。
